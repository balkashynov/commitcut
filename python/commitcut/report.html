CommitCutCode and setup instructions

Test your webhook after a crash.

CommitCut stops your app during a database request, restarts it, sends the same test webhook again, and checks the data in PostgreSQL.

This page shows saved results from real tests. It does not run the tests in your browser. The included examples use made-up payments and accounts.

    Choose when to stop the app

    Each button shows a separate test, starting with a reset database. “Before” stops the app before the request reaches PostgreSQL. “After” stops it after PostgreSQL finishes the request, before the app receives the reply.

    Result after restarting and retrying

    Pass: all SQL checks passed. Fail: a check found the wrong result. No result: the test could not finish or reliably check the result.

    Use it with your app

    Provide a command to start your app, a test webhook, SQL to reset the database, and SQL to check the result. Your app connects to a local test database through CommitCut. You do not need to add crash instructions to the app.

    commitcut scenario.toml --output evidence/run-1 # Exit 0: passed. 1: a check failed. 2: could not check.

    What these tests cover

    Only the app is stopped. PostgreSQL keeps running. Each test sends one webhook at a time. It does not test live Stripe payments, database crashes, failed disks, or every possible ordering of concurrent requests.

    These checks do not cover emails, calls to other services, or work put on a queue. Those need separate tests.
